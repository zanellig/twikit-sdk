# Cookie Session Import And Persistence

## Parent

.scratch/typescript-sdk-foundation/PRD.md

## What to build

Implement cookie-session storage for the MVP using `tough-cookie`, including in-memory storage, filesystem-backed storage under the runtime helper export, cookie-header import, structured cookie import, CSRF extraction from `ct0`, set-cookie persistence, duplicate `ct0` cleanup behavior, and session-file secret handling.

## Acceptance criteria

- [x] Consumers can import cookies from a browser-style cookie header string and from structured cookie objects.
- [x] Cookie parsing and jar behavior use `tough-cookie` rather than ad hoc cookie parsing.
- [x] Session data persists structured cookies, optional user ID, and timestamps.
- [x] `MemorySession` works from the root export and `FileSession` works from the runtime-specific export.
- [x] The client can derive the CSRF token from `ct0` and expose it internally for request headers.
- [x] Response `set-cookie` values update the session store, including duplicate `ct0` cleanup compatible with the Python twikit behavior.
- [x] File-backed sessions are documented as secret-bearing files and use restrictive permissions where supported by the runtime.
- [x] Tests cover header import, structured import, persistence, set-cookie updates, duplicate `ct0`, and file storage without live network access.

### Key decisions

- **Duplicate ct0: keep-first.** Matches Python twikit's `_remove_duplicate_ct0_cookie` which iterates the jar and skips any ct0 after the first one seen.
- **Expired cookie handling.** `parseSetCookie` returns a discriminated union (`{ cookie }` vs `{ expired }`) so `handleSetCookieHeaders` removes cookies with `Max-Age=0` or past `Expires`. `buildCookieHeader` also skips stored cookies whose `expires` is in the past.
- **Cookie merge key.** Cookies are keyed by `name|domain|path` for merge/replace. This is more precise than Python twikit's flat `{name: value}` dict, which loses domain/path metadata.
- **Cookie header import defaults.** `parseCookieHeader` assigns `domain: ".x.com"`, `path: "/"`, `secure: true`, `httpOnly: true` since the `Cookie:` request header format carries no attributes. This is an extension over Python twikit which has no header-string import.
