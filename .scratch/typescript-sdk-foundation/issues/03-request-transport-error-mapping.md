# Request Transport And TwikitError Mapping

## Parent

.scratch/typescript-sdk-foundation/PRD.md

## What to build

Implement authenticated request execution and SDK error mapping. Requests should use session cookies, CSRF, bearer and X auth headers, language/user-agent options, injected fetch, response parsing, HTTP status mapping, GraphQL error-envelope mapping, domain operation labels, raw/headers metadata, and reset-only 429 rate-limit parsing.

## Acceptance criteria

- [x] Requests include the expected authenticated browser-like headers derived from client options and session state.
- [x] Network failures and HTTP failures throw `TwikitError` by default with stable `kind` categories.
- [x] GraphQL error envelopes map account-locked, account-suspended, duplicate tweet, and invalid media cases into stable error metadata.
- [x] Public errors include domain operation labels and do not expose internal GraphQL paths as the primary operation name.
- [x] 429 responses parse `x-rate-limit-reset` into `rateLimit.resetAt` and `rateLimit.resetEpochSeconds` when present.
- [x] Tests cover status mapping, GraphQL error mapping, raw/header preservation, operation labels, network errors, and 429 reset parsing.

### Implementation notes

- `src/internal/request-transport.ts` -- internal `RequestTransport` class, not re-exported from the package.
- 37 tests in `test/request-transport.test.ts`.
- HTTP status mapping runs before GraphQL envelope mapping so non-2xx status always wins (e.g. 429 preserves rate-limit metadata).
- Non-JSON response bodies (HTML error pages, empty bodies) are caught and mapped to `TwikitError` with the raw text preserved.
- GraphQL error extraction scans all `errors[]` entries (not just the first) and falls back to `extensions.code` per Python twikit behavior.
- Set-Cookie response headers are persisted back to the session store after every request.
- Landed in v0.0.4 (commit 1977323).
